### Ю3. Анализ кода и безопасный запуск (до 28 окт)
- Модуль `analysis`: вход код, выход `list[Finding]` и результат прогона (прошло, упало, превысило лимит).
- Правила (коды Finding): вы делаете `LONG_FUNCTION`, `UNUSED_VARIABLE`, `DEEP_NESTING`, `MISSING_RETURN`. Остальные четыре (`FLOAT_MONEY`, `BARE_EXCEPT`, `EVAL_EXEC`, `NO_INPUT_VALIDATION`) пишет Ангелина (А10) в `analysis/rules/`. Вы пишете `analysis/__init__.py` с функцией `analyze(code)`, которая собирает все правила из `rules/`.
- Запуск в отдельном Docker-контейнере: без сети, 5 секунд, 128 МБ, не от root. Бесконечный цикл и выход в сеть завершаются безопасно.
- Готово, когда: на решениях Андрея (`testdata/solutions/`) замечания находятся; тесты на запуск зелёные.

## Правила git (общие для всех)

1. В `main` напрямую не пушить. Только PR; слияние после зелёного CI и ревью.
2. Ветка на задачу: `feature/<задача>`. Свои ветки не удалять чужие, чужие вообще не трогать.
3. Перед PR: `git fetch` и `git merge origin/main` в свою ветку.
4. Один небольшой PR на задачу. После PR написать в чат и скинуть ссылку.
5. Реальных данных и секретов нет, только выдуманные данные; секреты из окружения.
