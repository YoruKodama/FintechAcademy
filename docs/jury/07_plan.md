# План внедрения и развития

План привязан к спринтам трека (спринт 2: 16-29 ноября, спринт 3: 3-8 декабря). Всё, что в списке, делаем после загрузки первого спринта; сроки оценка команды.

## Где мы сейчас (конец спринта 1)

Работает: API на FastAPI с PostgreSQL, 3 сценария, анализ кода по 8 правилам, три экрана (задача, результат, панель руководителя), обезличивание текста перед моделью, локальная модель через Ollama и адаптер GigaChat, оценщик баллов. Проверки в CI: 382 автотеста и сквозной тест в браузере. Измерено на 20 решениях эксперта: средняя ошибка 9,2 балла, 12 из 20 в пределах 10 баллов (`docs/eval.md`).

Известные ограничения (в плане ниже закрываем в первую очередь):
1. Оценка завышает самые плохие решения (около 20 баллов при эталоне 2-6).
2. Запуск кода кандидата в контейнере реализован, но в `docker compose` выключен.
3. Нет авторизации: любой видит панель руководителя.
4. Модель на процессоре отвечает около 33 секунд; нужен сервер с видеокартой для пилота.
5. Доказательная база по времени проверки кандидата опирается на интервью, которых пока мало.

## Спринт 3 (3-8 декабря): сценарий пилота и масштабирование

1. **Пилот.** Одно подразделение, группа из 10-20 сотрудников или стажёров, 2-3 недели. Критерии успеха заранее: сколько времени проверяющий тратит на кандидата (до и после), совпадение с оценкой эксперта, число пройденных сценариев на человека.
2. **Данные пилота.** Только обезличенные задачи и ответы; сценарии банка согласуются со службой информационной безопасности. Развёртывание в контуре банка без доступа к открытой сети (Ollama и обезличивание уже работают локально).
3. **Масштабирование.** Больше сценариев (SQL, работа с транзакциями, безопасность), импорт сценариев банком, интеграция со входом сотрудников и HR-системой банка, отчёты для руководителя по команде.
4. **Питч.** Демо основного сценария на работающем решении, метрики пилота, экономика и путь от пилота к внедрению.

## Риски и как с ними работаем

| Риск | Что делаем |
|---|---|
| Модель ошибается в оценке | Баллы ограничиваются правилами анализатора, результат объясняется замечаниями с номерами строк; решение остаётся за проверяющим |
| Утечка персональных данных | Обезличивание до любого вызова модели, модель локально; для облачных моделей данные только после обезличивания |
| Выполнение чужого кода | Только в контейнере без сети, ограничения по времени, памяти, процессам; атаки проверены (`docs/qa/security.md`) |
| Мало данных для доказательств | Интервью, пилот, расширенный эталонный набор |
