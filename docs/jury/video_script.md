# Сценарий видео-демо (2-3 минуты)

Запись экрана с голосом или подписями на русском. Показываем только то, что реально работает.

## Перед записью (10 минут)

1. Запустить стек: `cp .env.example .env`, `docker compose up --build`, открыть http://localhost:3000.
2. Чтобы разбор писала настоящая модель, в `.env` поставить `LLM_PROVIDER=ollama` и один раз выполнить
   `docker compose exec ollama ollama pull qwen2.5:7b-instruct`, затем `docker compose up -d --build backend`.
   Если модель не скачана или сервер слабый, оставьте `stub` и **скажите об этом в видео** (в разборе будет пометка).
3. Один раз пройти сценарий вхолостую: модель на процессоре отвечает около 30-50 секунд, лучше знать заранее.
4. Код для вставки лежит в `testdata/solutions/`: `s1_03_float.py` (с ошибкой) и `s1_01_excellent.py` (хороший),
   рядом `.json` с готовыми ответами на вопросы. Код **вставляйте** (Ctrl+V), а не печатайте: редактор сам расставляет
   отступы, и набранный вручную код ломается.
5. Закрыть лишние окна, увеличить масштаб браузера до 110-125 %.

## Что сказать обязательно и честно

- Если в видео стоит заглушка вместо модели: «Здесь стоит режим заглушки, баллы по правилам, настоящая модель работает так, как показано на замере».
- Запуск кода в контейнере в нашем `docker compose` выключен. Если спросят: «Код запускается только в контейнере без сети, мы проверили 14 атак, но в демо запуск отключён».
- Не говорите «точно» и «всегда» про качество оценки: в метриках есть завышение у плохих решений.

## Чего в видео не показывать

Реальные ключи, `.env`, настоящие фамилии и телефоны, чужие окна. Все тестовые данные выдуманные.

Загрузить файл на облачный диск, ссылку положить в `docs/jury/README.md` строкой «Видео-демо: …».
