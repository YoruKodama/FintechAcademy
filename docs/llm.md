# LLM-слой

Код лежит в `backend/app/llm/`. Весь остальной проект работает с моделью только через
интерфейс `LLMClient`, поэтому провайдер меняется переменной окружения, без правки кода.

## Интерфейс

```python
from app.llm import get_llm_client

client = get_llm_client()  # провайдер берётся из LLM_PROVIDER
answer = client.complete(system, user, temperature=0.0, max_tokens=800)
```

`complete` принимает системный и пользовательский текст и возвращает строку ответа.
Типы `Finding` и `Result` описаны в `app/llm/types.py`.

## Переменные окружения

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `stub` | Выбор провайдера: `stub`, `ollama` (позже `gigachat`) |
| `OLLAMA_URL` | `http://localhost:11434` | Адрес сервиса Ollama |
| `OLLAMA_MODEL` | `qwen2.5:7b-instruct` | Название модели в Ollama |

## Заглушка (`stub`)

`StubClient` не обращается к сети и возвращает заранее заданные ответы:

- если в системном промпте есть слово JSON, возвращается JSON с четырьмя критериями и разбором;
- иначе возвращается короткий текст.

Заглушка запоминает вызовы в `client.calls`, поэтому в тестах можно проверить, что именно
было отправлено модели. Для тестов достаточно `LLM_PROVIDER=stub` или `StubClient(...)` напрямую.

## Ollama (`ollama`)

`OllamaClient` ходит в `POST {OLLAMA_URL}/api/chat` с `stream: false`. Ко всем системным
промптам добавляется требование отвечать по-русски. Параметры запроса:

- таймаут 60 секунд;
- 2 повтора после первой неудачи (паузы 1 и 2 секунды) при отказе соединения, таймауте,
  ответе 5xx и пустом или сломанном ответе;
- модель не найдена (404) не повторяется, в ошибке сразу написана команда `ollama pull`.

Если модель недоступна, клиент бросает `LLMUnavailableError` с понятным текстом, а не падает
с трассировкой. Запросы идут только на `OLLAMA_URL`, во внешние сервисы ничего не отправляется.

Запуск локально:

```bash
ollama serve
ollama pull qwen2.5:7b-instruct
LLM_PROVIDER=ollama python -c "from app.llm import get_llm_client; print(get_llm_client().complete('Ты помощник.', 'Скажи привет.'))"
```

Предложение для `docker-compose.yml` (файл ведёт Юра, согласовать перед добавлением):

```yaml
  ollama:
    image: ollama/ollama
    volumes:
      - ollama-data:/root/.ollama
    ports:
      - "11434:11434"
# в backend: OLLAMA_URL=http://ollama:11434
# в volumes: ollama-data:
```

### Скорость ответа

Среднее время ответа на 5 тестовых решениях Андрея: **не замерено**. Замер делает
`scripts/eval.py` (колонка «время» в `docs/eval.md`) после появления `testdata/solutions/`.

## Обезличивание

Любой текст, который уходит в модель (код решения, ответы на вопросы), сначала проходит
`app.privacy.anonymize`:

```python
from app.privacy import anonymize, deanonymize

safe_text, mapping = anonymize(text)   # "Клиент [ФИО_1], тел. [ТЕЛЕФОН_1]"
shown = deanonymize(model_answer, mapping)  # вернуть значения, если нужно показать пользователю
```

Заменяются ФИО, телефоны, e-mail и номера карт. `mapping` («метка → значение») остаётся
у нас и в модель не отправляется. Как работает поиск:

- e-mail, телефоны и карты ищутся регулярными выражениями; слитные 16-19 цифр считаются
  картой только при верной контрольной сумме Луна, поэтому длинные числа в коде не страдают;
- ФИО ищутся по словарю русских имён, отчествам и окончаниям фамилий: «Иванов Пётр»,
  «Ивану Петровичу Сидорову», «Смирнов А.В.»; одиночное имя заменяется только после слов
  вроде «клиент», «меня зовут», «ФИО:».

Ограничения: одиночная фамилия без подсказки не заменяется, имена латиницей и слова
ЗАГЛАВНЫМИ буквами не ищутся. При необходимости можно подключить Natasha (работает локально).

## Промпты и формат ответа

Промпты лежат в `backend/app/llm/prompts/`, загружаются через `load_prompt(name)`:

| Файл | Для чего |
|---|---|
| `criteria.md` | четыре критерия по 25 баллов, что даёт 0, 10 и 25 баллов (подставляется в промпты) |
| `review_code.md` | разбор кода, замечаний анализатора и ответов на вопросы, основной сценарий |
| `evaluate_answer.md` | оценка одного ответа на вопрос (для отдельной проверки ответа) |

В основном сценарии достаточно одного вызова с `review_code`: так быстрее на локальной модели.
Промпты не содержат реальных данных, это проверяет тест.

Модель должна вернуть строго JSON:

```json
{"criteria": {"correctness": 0, "code_quality": 0, "safety": 0, "explanation": 0}, "feedback": "..."}
```

`complete_json(client, system, user)` вызывает модель и проверяет ответ (`parse_llm_answer`):
JSON достаётся даже из блока ` ```json ` или из текста вокруг, все четыре критерия обязательны,
баллы округляются и обрезаются до 0..25, `feedback` сокращается до 1200 символов.
Если формат сломан, делается один повторный запрос с напоминанием о формате.
Если и он неудачный, бросается `LLMResponseError`.

## Ошибки

Все ошибки наследуются от `LLMError`, и их текст можно показывать пользователю:

- `LLMConfigError` — неверная настройка, например неизвестный `LLM_PROVIDER`;
- `LLMUnavailableError` — модель недоступна;
- `LLMResponseError` — ответ модели не соответствует формату.
